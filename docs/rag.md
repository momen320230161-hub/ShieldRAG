# Baseline RAG (Task 04)

Authenticated Admin explicitly authorizes external processing of an approved original. The backend acquires a database lease, downloads private bytes, verifies original SHA-256, extracts in an isolated subprocess, chunks deterministically, and requests Gemini document embeddings. It checks the original again before publishing the entire index in one database transaction. No database transaction remains open during extraction or Gemini calls.

Search embeds the question with `RETRIEVAL_QUERY`, calls the existing SECURITY INVOKER `match_shield_chunks` with the caller's bearer token and publishable key, and rechecks trusted profiles and source metadata. RLS allows only approved, fully indexed, hash-matched, externally authorized content: public for Students, public/restricted for Admins. The server key never authorizes retrieval. Query results from another embedding model are excluded. Changing model requires Admin reindexing; during a mixed-model transition irrelevant older vectors can reduce recall, so reindex all participating documents before switching deployments.

Ask sends bounded authorized excerpts as untrusted JSON data with a separate fixed system instruction. It uses no tools. An empty result causes a fixed abstention without a generation call. Generated evidence must reference an actual retrieved chunk and contain an exact contiguous quote. Backend citations contain database-derived document names, UUIDs and PDF page numbers. Sources and current roles are checked again after generation; permission changes or index replacements cause abstention.

## Models and bounds

- Official `google-genai==3.3.0`. `gemini-embedding-001`, exactly 768 values, document/query task types, finite/nonzero checks and manual L2 normalization. The stored float32 vector norm is checked transactionally. [Google embedding documentation](https://ai.google.dev/gemini-api/docs/embeddings).
- Default generation: `gemini-3.5-flash-lite`, confirmed available with the configured key using an actual synthetic generation request. Both models are configurable. No automatic model fallback or dimension conversion.
- UTF-8 TXT; strict pypdf 7.1 PDF text extraction, page order and one page per chunk. No OCR, scripts, links, embedded programs or external PDF resources are executed.
- At most 10 MiB original, 200 PDF pages, 200,000 extracted characters, 128 chunks by default. Extraction: 15 seconds; full indexing: 180 seconds. Linux parser: 512 MiB address-space/15 CPU-second limits; Windows: subprocess timeout and parser decoding/work bounds, without a hard OS memory sandbox. [pypdf configuration](https://pypdf.readthedocs.io/en/7.1.0/modules/configuration.html).
- Chunk ceiling 550 whitespace words AND 1,800 UTF-8 bytes; overlap up to 80 words capped at one third of the preceding window. The byte bound deliberately produces smaller chunks than the suggested 500–800 tokens, especially for non-ASCII text, to conservatively stay below the embedding model's 2,048-token input limit without silently truncating. Oversized indivisible words fail explicitly. Chunk occurrences use page, word interval and content: equal text on pages 2 and 8 produces two sequential chunks, and equal text at distinct positions within a PDF page or TXT is retained. Reprocessing the exact same source interval is deduplicated. No page-crossing chunks. Chunk configuration version 2 invalidates the old text-only deduplication cache on an explicitly requested rebuild; existing documents are not automatically processed.
- Embeddings: batches of 8, provider concurrency 2 per process, at most 3 attempts for 429/500/502/503/504 with bounded exponential backoff. Permanent errors fail immediately. SDK internal retries disabled; 20-second provider timeout. Per-process 256-entry embedding cache uses model/task/content digest keys; raw text is not stored in cache keys. Cache/process restart can cause repeated calls; cached indexes avoid unchanged document embedding work.
- Question: 1–1,800 UTF-8 bytes, top_k 1–10 (default 5), similarity threshold default 0.35, context at most 12,000 characters. POST JSON bodies at most 8 KiB. Structured answer at most 4,000 characters. Settings enforce hard upper bounds.

## Index lifecycle and recovery

`not_indexed/failed → processing → indexed`; processing failure may transition only the exact owning lease to failed. Failure cleanup never deletes chunks: any earlier completed revision is retained but hidden by the existing indexed-only RLS. A concurrent processing job receives 409. Ten-minute leases allow recovery after a worker crash; retry after expiry. Publication requires the same job token, approved status, expected SHA and live Admin role. Complete replacement of chunks, state, stable revision ID and audit commits together; malformed later chunks roll the whole publication back.

A matching completed index is a read-only cache hit. `shield_begin_index` returns it without changing any document field or assigning a job token. Python verifies private original bytes and returns existing chunk IDs without extraction, Gemini calls or `shield_fail_index`. Transient Storage/metadata failures, Gemini outage, request timeout/cancellation and lost/uncertain begin acknowledgements preserve the completed record and chunks. An unconfirmed begin response never establishes cleanup ownership. An explicit rebuild due to changed chunk/model configuration creates a processing lease; if it fails, old chunks remain hidden until a successful retry rather than being restored as the newly requested configuration.

Confirmed SHA mismatch, recognized missing original, invalid canonical reference, excessive stored size or missing original hash invokes `shield_invalidate_index`. This narrow server-only RPC reuses `shield_record_integrity_failure` and commits its deduplicated audit event together with `indexed → failed` for the observed completed revision. It clears `indexed_sha256` and retains chunk rows. Both Student and Admin retrieval are then denied by unchanged RLS. Each publication stamps `index_revision_id` with its job UUID; an obsolete verification/audit retry cannot invalidate a newer publication or an active processing lease. Legacy completed revisions with a null revision ID are handled without a data backfill. Infrastructure errors are never classified as confirmed missing content solely because a request timed out or returned 5xx.

`document_index_started`, `document_indexed` and `document_index_failed` audit events contain static reasons and trusted actor/document references. Confirmed original-byte failures use the existing persistent integrity audit. An unavailable audit remains denied with 503. If failure cleanup itself is unavailable, logs identify the document UUID for reconciliation; its processing chunks remain hidden and the lease expires. A lost publication acknowledgement may return 503 even if committed; a subsequent retry verifies the cached index. No durable background job queue is added.

The original forward migration `20261115143019_shieldrag_atomic_baseline_rag` adds index metadata, three service-only write RPCs and strengthens chunk RLS/RPC conditions. Task 04.1 adds `20261115150450_shieldrag_cached_index_integrity_hardening`: one nullable revision column, corrected existing write functions and one service-only integrity-invalidation RPC. All remain SECURITY INVOKER with fixed empty search paths; anon/authenticated cannot invoke the writes. No existing migration was edited or replayed; no RLS policy changed. Legacy chunks lacking verified index metadata remain invisible until explicit approved indexing. No production-like documents are reindexed automatically.

If the audit/invalidation transaction itself cannot be confirmed, the indexing request returns 503 and logs only trusted UUIDs for operator reconciliation. A lost successful acknowledgement is retried once with the same event UUID. A database outage cannot provide a guaranteed durable revocation; no destructive deletion is used as a fallback. If the transaction never commits, its revision change and audit are both absent. Investigate this operational failure before resuming use of the affected document.

After confirmed tampering or loss, an authorized operator must restore the exact original bytes matching the immutable SHA-256 before an Admin can successfully rebuild. There is no application endpoint that changes the stored original or its hash to bypass integrity checks.

## External processing and remaining limits

`external_processing_authorized:true` is mandatory for each indexing request, including restricted documents. This records the authenticated Admin's affirmative authorization to send extracted text to Google's configured Gemini service. Asking/searching also sends the question and, for generation, authorized excerpts externally. Operators must authorize that service and applicable residency/retention terms before use. RLS controls database access; it does not supply third-party confidentiality or residency guarantees.

Known configured credentials and common secret/JWT formats are rejected before model calls; generated known credentials are denied. Validation and provider errors omit raw inputs and upstream diagnostics. These guards do not detect every unknown secret in arbitrary source text. Do not upload secrets; enforce suitable admission controls.

Citation existence and exact quotes are deterministic checks; semantic entailment of every generated claim is not guaranteed. Prompt injection, hallucination, malicious documents and misleading citations remain baseline risks despite instruction separation and RLS. Task 05 adds a separate [Security Agent pipeline](security-agent.md); baseline behavior remains available with all existing authorization safeguards. Comprehensive evaluation remains future work. Deploy behind HTTPS, per-user rate limits and resource controls; per-process concurrency is not a deployment-wide quota.

Chat endpoints are intentionally stateless. Existing chat tables contain content/owner fields but have no write policies, stored citation provenance or permission-aware history contract. Adding persistence safely expands scope; it remains a separate task. No chat history enters the prompt or bypasses current document permissions.

## Swagger walkthrough

Start the backend using [setup](backend-setup.md), open `/docs`, and authorize a synthetic account bearer token. Upload a PDF/TXT and approve as Admin. Call `POST /api/v1/documents/{id}/index` with `{"external_processing_authorized":true}` only after authorizing external transfer. Authorize Student or Admin and call `/api/v1/rag/search` or `/api/v1/rag/ask` with `{"question":"What does the approved document say?","top_k":5}`. See [API contracts](api-contracts.md) and [testing](testing.md).

For the secure pipeline, send the same body and bearer token to `/api/v1/rag/secure-ask`. Input analysis precedes embedding. All authorized context is screened before generation, and a single non-allow blocks the request. Gemini is instructed to return one contiguous extract. The backend verifies that the answer occurs inside an exact quote from a cited chunk, then applies the shared current-permission and source checks. All secure responses require an audit acknowledgement. Exact extracts can omit qualifiers or reproduce misleading source material. Questions requiring translation, synthesis or paraphrase can lose answer availability under this policy. The baseline retains its existing generation behavior. See [Security Agent policy](security-agent.md).
